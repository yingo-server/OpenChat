# OpenChat 路线图

> 状态以代码与 `docs/lts-checklist.md` 为准。本文件只列方向与判据，不承诺日期。

## 已完成

### v1.0 — 可部署的骨架
分层 socket 架构（总线/桥接/用户/管理/数据五层）、SQLite 热库 + Postgres 冷库分域设计、
管理 REST + TUI 后台、认证全套、单二进制内嵌双 SPA、systemd + Caddy 部署件。

### v1.1（LTS 基线）— 把设计变成可用的产品
- 消息闭环：已读/送达回执、输入中、在线状态、成员变更通知、消息撤回
- 媒体：客户端生成缩略图与波形（服务端不需要 ffmpeg）、缩略图落文件系统 + 配额
- 通话：WebRTC 1v1 语音/视频，服务端只转发信令、媒体流 P2P
- 交互：CLI/TUI 双模式、中英双语、`opchat` 纯 TUI 管理台、管理后台 Dashboard
- 工程：全平台构建矩阵（5 架构 × 2 平台）、压测工具、文档自动校验（doccheck）
- 可靠性：热库真实收缩（归档删除 + trim + GC）、广播异步扇出 + 聚合、
  成员缓存、群人数上限、审计覆盖破坏性操作

## 下一版（v1.2）

按"不修就会出事"的优先级排序。

### 1. 冷库真正可用（生产准入）

**为什么**：`cold_dsn` 需部署层注册 driver；未注册时审计只写日志不落盘、
历史搜索退化为只搜热库 90 天。合规部署要求审计可追溯数年，这项目前做不到。

**怎么做**：把 pgx 驱动注册进装配（`server/cmd/chatd`），冷库不可用时按
`require_audit_store` 显式拒启（已有开关，只是驱动没接）。

**判据**：配好 `cold_dsn` 后 `openchatctl doctor` 的 `audit_store` 为 OK；
撤回/成员变更/通话的审计事件能在冷库 `sys.audit_log` 里按 since_id 翻到；
`GET /api/v1/audit` 返回真实数据而非降级日志。

### 2. 供应商接入（生产准入）

**为什么**：短信/邮件/图形验证码只有接口缝，生产环境注册登录不可用。

**怎么做**：`SMSSender` / `Mailer` / `CaptchaVerifier` 三个接口各实现一个供应商适配器
（国内短信建议阿里云或腾讯云，图形码建议极验或腾讯防水墙），配置驱动选择。

**判据**：生产配置下真实手机号能收到验证码并登录；邮箱能收到魔法链接；
第 2 条 OTP 起强制图形码且无法绕过。

### 3. 移动端推送 + PWA

**为什么**：没有推送，手机锁屏就收不到消息 —— 移动端实质上不可用。
这是与微信/QQ 差距最大的一项。

**怎么做**：PWA（manifest + service worker + 离线缓存）先让手机浏览器可"添加到主屏"；
推送走 Web Push（VAPID）或接厂商通道（FCM/APNs/国内厂商）由部署方选择。

**判据**：手机添加到主屏后能正常收发；App 在后台时收到系统通知；
点击通知直达对应会话。

### 4. 群治理

**为什么**：现在群只有"成员 + 角色"骨架，没有禁言/进群审批/群文件，
开不了真正的群。

**怎么做**：禁言（全员/单人/定时）、进群审批、邀请链接、群文件列表。
数据结构上 `conv_members.muted_until` 已有，主要是接口与 UI。

**判据**：群主可禁言某人 1 小时且该成员发消息被拒；新成员需群主批准才进群；
群文件可上传下载。

### 5. 消息体验补齐

**为什么**：@提及、引用回复、撤回 UI 都还差最后一公里（服务端与协议都在，
前端 UI 未接线）。

**判据**：长按消息能引用回复并在气泡里显示引用块；@某人后对方收到高亮提醒；
撤回按钮可用且 2 分钟后自动变灰。

## 明确不做（附理由）

| 项 | 理由 |
|---|---|
| 朋友圈 / 动态 | 那是社交产品，不是 IM 内核 |
| 支付 / 红包 | 涉及金融合规，与自托管定位冲突 |
| 公众号 / 小程序 | 生态型功能，需要平台方角色 |
| 自建 SFU 群通话 | 需要独立服务与带宽预算；v1.2 先用云 SFU（LiveKit/Twilio）过渡 |
| split 多进程部署 | 单机 2C2G 已够用；拆分留给真正需要水平扩展的部署方 |
| 端到端加密（E2EE） | 涉及密钥托管与多设备协商，需要独立设计与审计周期；
消息表已预留 `payload`/`envelope` 字段，不属于 v1.2 范围 |
